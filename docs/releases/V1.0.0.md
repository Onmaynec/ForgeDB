# ForgeDB v1.0.0 — Stable General Availability

Первый стабильный релиз встроенного key-value хранилища на Rust с CLI для Windows и Linux (x86-64). Основная цель обновления — проверяемый перенос данных, безопасное обслуживание и воспроизводимая публикация настоящего GitHub Stable Release вместо Pre-release.

## Главное

**Логический экспорт и восстановление.** Новые команды forgedb export и forgedb restore используют отдельный бинарный формат LOGICAL_ARCHIVE V1 с версиями и CRC32C Castagnoli. Экспорт включает действующие default/named Column Families и произвольные бинарные key/value, включая большие значения. Перед чтением фиксируется индивидуальный MVCC snapshot для каждой family; общего атомарного snapshot между разными families нет. Архив не шифрует данные и не подписывает их.

Экспорт создаёт временный файл в каталоге назначения, синхронизирует его и публикует без перезаписи существующего. Восстановление разрешено только в **новый** каталог. Все данные сначала записываются в staging, затем проверяются CRC32C, границы записей, версии, порядок ключей и EOF. Публикация происходит только после успешного закрытия восстановленной базы; при обычной ошибке staging удаляется. Имена families сохраняются, numeric IDs могут быть перенумерованы. См. docs/formats/LOGICAL_ARCHIVE_V1.md.

**Read-only диагностика.** Команды forgedb version и forgedb doctor <database> [--deep] помогают проверять установленную версию, recovery plan и целостность. Doctor не выполняет ремонт, удаление orphan или миграцию. Привычные GET/SCAN в CLI теперь не создают отсутствующую базу из-за опечатки в пути.

**Подбор файлов при диапазонном чтении.** На непересекающихся SST уровня L1+ поиск границы для SCAN выполняется бинарно: O(log N + K) вместо перебора всех SST уровня. На перекрывающихся L0 остаётся полный newest-first обзор, а точная проверка Included/Excluded границ, snapshot, tombstones и lifetime VersionSet сохраняется.

**Стабильная упаковка.** Новый workflow сначала проверяет release commit и делает annotated tag v1.0.0, затем собирает CLI из этого тега на Windows/Linux и проводит end-to-end smoke put/doctor/export/restore/get. Архивы и SHA-256 проверяются до публикации. GitHub Release сначала Draft и становится Stable (draft=false, prerelease=false) только после появления всех четырёх проверенных вложений.

## Проверки

CI: Ubuntu stable, Windows stable и Rust 1.89. Обязательны rustfmt, Clippy с -D warnings, workspace tests/all features, doctests, cargo doc, release build, benchmarks и новые тесты:
- stable_ga_cli: version/doctor, no-create GET/SCAN, перенос трёх families, бинарный ключ и 128-KiB value, tombstone, corruption/truncation/future-version, refusal to overwrite;
- stable_range: Included/Excluded/Unbounded bounds, snapshot и tombstone после compaction и reopen;
- CRC32C known vector 123456789 → E3069283.
Старые crash/recovery/WAL/MVCC/FQL/Windows regression suites остаются обязательными.

## Что НЕ заявляется

- Mixed-family atomic WAL и cross-family consistent snapshot отсутствуют (Issue #35).
- Полный process-wide OS file descriptor budget отсутствует (Issue #31).
- Название пакета forgedb занято в crates.io; GitHub binaries/source доступны, публикация именно этого crate в registry не заявляется (Issue #27).
- Нет сетевого SQL-сервера, репликации, encryption, authentication, secure deletion или криптографической защиты архива.
- CRC32C — обнаружение случайных повреждений, не защита от активного атакующего; гарантий SLA/нулевой потери данных при любых power failures нет.

Старые persisted файлы WAL V1, SSTable V1, MANIFEST reader V1–V2/writer V2, CURRENT V1, IDENTITY V1 и CF_REGISTRY V1 не меняются. Базы v0.9.0 открываются без миграции. Вся граница GA: docs/GA_READINESS.md, docs/COMPATIBILITY.md, docs/adr/0020-stable-ga-portable-archive.md и docs/RELEASE_POLICY.md.
