# ForgeDB v0.8.0 — FQL & Interactive Shell

## Изменения

- Добавлен FQL V1 — строгий CLI query language над существующим ColumnFamilies API: SHOW FAMILIES, CREATE/DROP FAMILY, USE, PUT, GET, DELETE, SCAN FROM/TO/LIMIT, BEGIN/COMMIT/ROLLBACK, HELP, EXIT.
- Одноразовые команды: forgedb fql <directory> "<statement>" [--read-only].
- Интерактивный shell и скрипты: forgedb shell <directory> [--read-only] [--file <script.fql>]. Shell работает с redirected stdin.
- Поддержаны quoted UTF-8 и binary literals, escape \xHH и X'HEX'. Вывод GET/SCAN имеет обратимый quoted формат.
- Lexer проверяет размер statement 64 KiB, число токенов 512; SCAN ограничен 100 строками по умолчанию и 10000 максимум.
- Ошибка statement не запускает частичный write. Script fail-fast с номером строки, REPL после ошибки продолжает работу. Незавершённый BEGIN откатывается при EXIT, EOF и ошибке script.
- Транзакции используют существующий optimistic snapshot isolation и WAL Sync выбранной Column Family. Собственные writes видны GET.

## Пример

    forgedb fql ./data "PUT account 'Alice Smith'"
    forgedb fql ./data "GET account" --read-only
    forgedb shell ./data

Содержимое commands.fql:

    CREATE FAMILY users
    USE users
    BEGIN
    PUT user42 'Alice'
    GET user42
    COMMIT
    SCAN FROM user TO userz LIMIT 20
    EXIT

Запуск:

    forgedb shell ./data --file commands.fql

## Ограничения

- FQL — не SQL: нет SELECT, JOIN, таблиц или query optimizer.
- Одна строка — одна команда, завершающая точка с запятой необязательна.
- SCAN внутри BEGIN запрещён до корректного transactional range merge. USE, CREATE/DROP FAMILY также недоступны внутри BEGIN.
- Скрипты не атомарны целиком: committed строки до ошибки остаются durable, незакоммиченный BEGIN откатывается.
- Межсемейные atomic batches, глобальные snapshots/transactions и FD budget не добавлены.
- Read-only CLI не создаёт файлы, изменяющие команды отклоняются.
- FQL writes вне BEGIN используют WriteOptions::sync(). Нет изменений WAL/recovery semantics.

## Persisted compatibility

Никаких новых on-disk форматов. IDENTITY V1, WAL V1, Internal Key V1, SSTable V1, MANIFEST writer V2/reader V1–V2, CURRENT V1 и CF_REGISTRY V1 не меняются. Миграция старых баз не нужна.
