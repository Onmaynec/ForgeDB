# ForgeDB v0.2.0 — SSTable and Flush

> Статус: **draft / не выпущено**. Тег и GitHub Pre-release разрешены только после полного зелёного gate.

`v0.2.0` переводит ForgeDB от WAL-only базы к первому полноценному persisted LSM-слою: immutable memtable, SSTable V1, MANIFEST V1, WAL generations и crash-safe synchronous flush.

## Основные возможности

- SSTable V1 с фиксированными header/footer;
- checksummed data, index, Bloom filter и properties blocks;
- prefix compression и restart points;
- bounded decoding всех persisted lengths и offsets;
- MANIFEST V1 с checksummed `VersionEdit` frames;
- crash-safe `CURRENT`;
- numbered WAL generations;
- mutable/immutable memtable lifecycle;
- `Database::flush()`;
- point reads `mutable → immutable → L0 newest-first`;
- восстановление current и previous WAL;
- удаление obsolete WAL только после durable SST installation;
- fail-safe открытие при отсутствующих или повреждённых live-файлах.

## Исправленные release-critical сценарии

### Previous/current WAL больше не смешиваются

После падения между rotation edit и SST installation previous WAL восстанавливается в отдельную immutable memtable, а current WAL — в mutable. Это предотвращает потерю previous generation при повторном flush и втором crash.

### WAL публикуется раньше CURRENT

При создании новой базы initial WAL создаётся и синхронизируется до MANIFEST/CURRENT. Как только `CURRENT` становится authoritative, recovery может строго требовать указанный WAL и никогда не пересоздаёт его молча.

### Безопасный retry bootstrap

Если crash оставил header-only initial WAL, он повторно используется только после проверки UUID, file number и отсутствия frames/tail. При отсутствии `CURRENT` разрешено удалить только доказанные reserved bootstrap artifacts:

- `MANIFEST-000001`;
- `MANIFEST-000001.tmp`;
- `CURRENT.tmp`.

Неизвестные и пользовательские файлы сохраняются.

### Безопасный retry WAL rotation

Если crash или ошибка оставили следующее WAL-поколение до публикации rotation edit, flush может повторно использовать только проверенный header-only файл. WAL с complete frame или partial tail не удаляется, не обнуляется и блокирует flush с corruption error.

### Retry-safe SST build

Повторный flush может удалить только temp/final SST с тем же доказанным reserved number, если этот номер отсутствует в live MANIFEST state. Любой другой orphan SST игнорируется normal read path и не удаляется автоматически.

### Missing live WAL — corruption

Если существующий MANIFEST ссылается на отсутствующий current или previous WAL, open завершается ошибкой. Создание пустого replacement WAL запрещено, поскольку могло бы скрыть потерю подтверждённых данных.

### Close не публикуется раньше sync

`Database::close()` устанавливает состояние closed и освобождает lock только после успешной синхронизации WAL и MANIFEST. Во время активного flush close возвращает `Busy`.

## Persisted-форматы

Новая версия формата не заменяет существующие V1-контракты. Добавлены SSTable V1, MANIFEST V1 и CURRENT V1.

| Формат | Reader | Writer |
|---|---:|---:|
| IDENTITY | 1 | 1 |
| Internal Key | 1 | 1 |
| WAL | 1 | 1 |
| SSTable | 1 | 1 |
| MANIFEST | 1 | 1 |
| CURRENT | 1 | 1 |

Будущие версии форматов отклоняются как unsupported. Mid-file corruption и checksum mismatch не обходятся resynchronization.

## Тестовое покрытие в ветке

- reopen после flush;
- point reads через mutable, immutable и несколько L0 SSTables;
- tombstone и overwrite после flush;
- deterministic model через несколько flush/reopen;
- checksum corruption live SST;
- orphan SST не влияет на authoritative reads;
- missing MANIFEST-owned WAL;
- recovery previous/current WAL в разные memtable;
- retry после initial header-only WAL;
- cleanup reserved bootstrap artifacts без удаления user file;
- запрет reinitialize при существующем CURRENT;
- retry header-only orphan next WAL;
- отказ повторного использования non-empty orphan next WAL;
- strict SSTable/MANIFEST/WAL version, UUID, number, length и checksum validation.

## Известные ограничения

- только Level 0;
- нет leveled compaction;
- нет snapshots и range iterator;
- flush синхронный;
- SSTable reader v0.2 bounded-загружает файл целиком;
- нет background flush worker и write stalls;
- нет CLI inventory/verify;
- normal open не удаляет произвольные orphan/unknown files.

Эти возможности запланированы на `v0.3.0+`.
