# ForgeDB v0.5.0 — MVCC Transactions

## Цель milestone

v0.5.0 добавляет optimistic snapshot-isolation transactions поверх уже существующих MVCC snapshots, WAL atomic batches и snapshot-aware compaction retention.

Главный принцип реализации: transaction commit не создаёт второй write path. После conflict validation весь write set проходит существующий `Database::write` как один `WriteBatch`.

## Выполнено

- Добавлены публичные `Transaction` и `TransactionState`.
- Добавлен `Database::begin_transaction()`.
- Snapshot фиксируется при `BEGIN`.
- Reads внутри transaction видят own buffered writes поверх snapshot.
- `put` и `delete` буферизуются до commit.
- Реализован rollback без WAL mutation.
- Реализована write-write conflict validation по committed sequence numbers.
- Conflict lookup охватывает mutable memtable, pending immutable memtable и live SSTables.
- Validation и WAL append сериализованы одним public write gate.
- Commit использует один atomic `WriteBatch`.
- `Sync` и `NoSync` используют существующие durability semantics.
- `DisableWal` для transaction commit запрещён.
- Active transaction удерживает зарегистрированный snapshot, поэтому compaction учитывает его через `oldest_active_snapshot_sequence`.
- Transaction read metadata ограничены числом уникальных ключей и суммарной длиной ключей; oversized keys отклоняются до allocation.
- CLI получил `forgedb transaction` / `forgedb tx` с `--put`, `--delete`, `--get`, `--rollback`, `--sync`, `--no-sync`.
- CLI `Conflict` получает стабильный exit code `9`.
- Добавлены tests own-write visibility, rollback, same-key conflict, sequence-based conflict, SSTable conflict lookup, disjoint commits, snapshot stability, `DisableWal` rejection и reopen recovery.
- Добавлены проверки memory budget read set, конкурентных commits одного ключа и snapshot retention при leveled compaction.

## Isolation contract

ForgeDB v0.5.0 предоставляет snapshot isolation с обязательной write-write conflict detection.

Не заявляются:

- serializable isolation;
- full read-write conflict detection;
- predicate/range locking;
- phantom protection;
- write-skew prevention;
- nested transactions;
- savepoints;
- automatic retries.

Подробный нормативный контракт: `docs/TRANSACTIONS.md`.

## Crash-consistency impact

Новый persisted transaction format не появляется.

Transaction commit кодируется как обычный WAL V1 `WriteBatch` frame. Поэтому recovery либо декодирует и применяет полный committed batch, либо не применяет его; частичное восстановление отдельных operations из одного transaction batch не допускается существующим WAL contract.

Conflict validation не изменяет persisted state. При конфликте WAL append не выполняется.

`DisableWal` запрещён, чтобы transaction API не создавал скрытый режим, в котором atomic commit acknowledged без WAL protection до flush.

## Persisted-format impact

Нет изменений persisted layout.

| Формат | Read support | Write support |
|---|---|---|
| IDENTITY | 1 | 1 |
| Internal Key | 1 | 1 |
| WAL | 1 | 1 |
| SSTable | 1 | 1 |
| MANIFEST | 1, 2 | 2 |
| CURRENT | 1 | 1 |

Compatibility fixtures v0.4 остаются применимыми.

## Performance note

SSTable conflict validation в v0.5.0 намеренно correctness-first: подходящие tables читаются существующим bounded validated decoder. Это может быть дороже будущего indexed conflict lookup, но сохраняет checksums, bounds и sequence semantics.

Оптимизировать этот путь следует в v0.6.0 только после benchmark и без ослабления conflict invariants.

## CLI examples

```bash
forgedb tx ./database \
  --put account:1 100 \
  --delete pending:1 \
  --sync
```

```bash
forgedb tx ./database --get account:1 --put account:1 150 --get account:1 --sync
```

```bash
forgedb tx ./database --put temporary value --rollback
```

## Известные ограничения

- Полный FQL parser/shell остаётся milestone v0.8.0.
- Read set bounded и tracked, но v0.5.0 не валидирует его на read-write conflicts.
- Conflict keys возвращаются caller-у как binary bytes; caller отвечает за безопасное логирование.
- Background compaction worker pool и transaction-specific metrics ещё отсутствуют.
- Physical obsolete SST reaper остаётся консервативным ограничением v0.4/v0.5.
