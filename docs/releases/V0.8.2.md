# ForgeDB v0.8.2 — Streaming SST Handle Pool

Вторая часть улучшений ресурсоёмкости SST после v0.8.1. Теперь потоковые scan cursors и чтение входных файлов для compaction пользуются общим LRU-кэшем файловых дескрипторов с point GET.

## Что изменено

- `SstEntryCursor::open_pooled` закрывает выделенный `File` после полной проверки SST metadata/index/footer/filter и первого блока. В дальнейшем курсор читает очередные data blocks через `Arc<TableHandlePool>` вместо собственного долгоживущего FD.
- `Database::scan` теперь подключает курсоры к pool текущего `VersionSet`. Сохранённые iterators по-прежнему пиннят исходное поколение `VersionSet`, поэтому compaction/retired cleanup не удаляет используемые файлы.
- Компактация переходит на `read_entries_pooled`, последовательно читает data blocks через общий pool вместо полного `fs::read` для каждого input SST. Merge по-прежнему материализует bounded entries, контролируемые `max_compaction_bytes`.
- `Options::table_cache_capacity` теперь ограничивает resident SST File pool не только при GET, но также при block-by-block scan и чтении входных SST compaction внутри одного Database. `table_handle_stats()` отражает общий pool: capacity, open_handles, hits, misses, evictions, reopens.
- При окончательной очистке retired SST удалённый номер исключается из списка уже открывавшихся файлов (`seen`), чтобы его учёт не накапливался неограниченно.
- Проверки CRC32C каждого data block, identity и размера файла при повторном открытии сохранены. Нарушения возвращаются как ошибка, а не пропускаются.

## Регрессионные проверки

- `scan_many_sst_with_capacity_one_and_reopen_preserves_order_and_bytes`: 48 SST с 480 entries при вместимости LRU=1. Проверяется порядок, bytes, reopens и reload базы.
- `concurrent_get_and_streaming_scans_share_one_fd_budget`: четыре worker с GET одновременно с диапазонным scan, общий pool capacity=1.
- `compaction_inputs_use_bounded_pool_and_cleanup_preserves_old_scan`: компактация многоблочных inputs, прежний iterator удерживает старые SST, cleanup сначала откладывает, затем удаляет.
- Отдельный `#[ignore]` stress `ignored_stress_thousand_sstable_scan` рассчитан на 1024 SST и **не** засчитывается как пройденный в стандартном CI.
- Существующие тесты WAL, recovery, MVCC, FQL и named Column Families продолжают работать.

## Гарантии и границы

`table_cache_capacity` — **resident FD budget внутри одного SST read pool**, а не OS-wide или process-wide limit. При initial metadata validation каждый cursor кратковременно держит отдельный FD, который закрывает до публикации cursor; при одном таком open число одновременно открытых FD процесса может превысить `table_cache_capacity`. SST outputs, WAL, MANIFEST, LOCK, deep verify и другие named Column Families также открывают собственные файлы вне этого pool. При нескольких параллельных `scan` всё ещё возможны кратковременные validation opens. Общая задача #31 остаётся открытой.

`block_cache_size` отдельно ограничивает decoded-block residency. Сравнимого performance benchmark до/после нет: общий mutex может замедлять одновременное чтение из нескольких файлов. Гарантий снижения RSS или увеличения throughput не заявляется.

## Совместимость

Persisted IDENTITY V1, WAL V1, SSTable V1, MANIFEST reader V1–V2/writer V2, CURRENT V1, CF_REGISTRY V1 не меняются. Обновления структуры на диске и миграции для базы v0.8.1 не требуется. Команды CLI `forgedb fql`, `forgedb shell` и `forgedb cf` работают как раньше.
