# ForgeDB v0.6.1 — Stability and Recovery

## Назначение

Исправительный выпуск поверх v0.6.0. Цель — убрать риск ложного успешного `close()` после ошибочного sync, сделать заполнение mutable memtable штатным для последовательных публичных записей и автоматически освобождать уже доказанно устаревшие SSTable, когда ими больше не пользуются читатели.

## Исправления

### Закрытие базы

`Database::close()` удерживает mutex состояния, синхронизирует WAL и MANIFEST по существующим writer handles, затем помечает базу закрытой и освобождает writer handles и native LOCK. Ошибка sync оставляет handles и LOCK на месте. Повторный вызов может выполнить sync заново; повторный успешный close идемпотентен. `lock_state()` также проверяет `closed` уже под mutex, чтобы запрос не проскочил через гонку с закрытием.

Сценарий WAL-sync failure и MANIFEST-sync failure тестируется через deterministic callback injection; дополнительно проверяются lock retention, retry, успешный reopen и чтение данных. Это тест логики закрытия, не эмуляция физического power loss.

### Записи при заполненной memtable

Публичные `put`, `delete`, `write` при ошибке `ResourceLimit { resource: "memtable_memory", .. }` один раз выполняют synchronous flush и повторяют исходную операцию под общим public write gate. Preflight отклоняет операцию до WAL append, поэтому первая попытка не оставляет частично записанный batch. После второго отказа ошибка возвращается caller-у; infinite retry нет.

Это **не** background flush. Длительность `put/delete/write` может увеличиться из-за I/O и compaction. Transaction commit намеренно остаётся на прежнем write path.

### Очистка retired SSTable

После успешного `compact_range` и автоматического leveled compaction запускается best-effort `cleanup_obsolete_sstables()`. Как и ранее, очередь содержит только input SST, выведенные из live topology synced MANIFEST edit. Удаление откладывается, если любой прежний `TableReader` ещё жив, включая reader из активного iterator; Windows delete semantics соблюдаются через lifetime pinning.

Ошибка удаления не меняет итог уже установленной compaction. Невыполненное удаление остаётся доступным для явного `Database::cleanup_obsolete_sstables()`, возвращающего подробный `CleanupReport`. Process-local retirement queue не восстанавливается после restart; произвольные orphan-файлы **не** удаляются.

### Технический долг

- Удалены исходники pre-MVCC базы, не включённые в действующую библиотеку.
- README, ARCHITECTURE, SECURITY, validation contract и комментарии API приведены к текущей реализации.
- В `Options` уточнено, что `table_cache_capacity` и параметры background worker jobs пока не управляют соответствующими подсистемами.
- `include!`-композиция storage core и legacy materialized scan пока остаются, чтобы не смешивать patch с крупным refactor.

## Совместимость

Не изменены persisted WAL V1, SSTable V1, Internal Key V1, CURRENT V1 и MANIFEST V2 (reader V1/V2). Прежние директории баз доступны без migration; API текущих методов сохранён.

## Регрессионные проверки

- WAL/MANIFEST sync failure -> retryable close.
- Повторный успешный close и успешный reopen.
- Повторяющиеся writes после автоматического flush и чтение после reopen.
- Oversized atomic WriteBatch: без частичной публикации.
- Освобождение SST после compaction без readers.
- Отложенное освобождение при активном iterator.
- Snapshot retention и сохранение неопознанных orphan SST.

CI требует Ubuntu stable, Windows stable, Rust 1.89, форматирование, strict Clippy, workspace tests, doctests и release build. Подтверждённый run ID фиксируется отдельно после завершения проверок.

## Оставшиеся ограничения

Полная restart-aware garbage collection требует отдельного протокола ownership. Фоновые flush/compaction workers, fully streaming compaction, lazy SST reader buffers, отдельные CLI binaries и изменения уровня изоляции не являются частью storage-code patch.
