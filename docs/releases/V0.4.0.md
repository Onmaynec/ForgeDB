# ForgeDB v0.4.0 — Leveled Compaction

## Goal

Сделать physical L1+ частью crash-recoverable storage model, не меняя WAL V1 и SSTable V1.

## Реализовано

- MANIFEST V2 с persisted `level + TableMeta` для L1+;
- чтение MANIFEST V1 и V2;
- crash-safe V1 → V2 rotation на writable open;
- L0 overlap-closure picker;
- Ln → Ln+1 picker по level size target;
- inclusion всех overlapping target-level inputs;
- checked `max_compaction_bytes` budget;
- canonical internal-key merge;
- snapshot-aware version retention;
- bottommost tombstone dropping;
- output splitting без разрыва одного user key;
- durable reservation output file numbers;
- atomic delete-input/add-output MANIFEST installation;
- synchronous auto-compaction после flush;
- bounded L0 slowdown и stop backpressure;
- `Database::compact_range`;
- CLI `compact`;
- reopen test после L0 → L1.

## Persisted-format impact

MANIFEST повышен с V1 до V2. V1 не изменён задним числом.

```text
Format          Read support   Write support
IDENTITY        1              1
Internal Key    1              1
WAL             1              1
SSTable         1              1
MANIFEST        1,2            2
CURRENT         1              1
```

Writable open старой базы после successful migration публикует V2; после этого ForgeDB v0.3.x должен корректно отказать из-за future MANIFEST version.

## Crash consistency

Compaction имеет два persisted boundary:

1. reservation edit продвигает `next_file_number` до создания outputs;
2. installation edit атомарно заменяет input references output references.

Crash до installation не меняет authoritative logical state. Crash после synced installation использует outputs. SST, созданный между boundaries и не установленный в MANIFEST, остаётся unreferenced и не включается normal recovery автоматически.

## Snapshot safety

Для каждого key сохраняются:

- newest version;
- все versions новее oldest active snapshot;
- первая version с sequence не выше oldest active snapshot.

Это покрывает active snapshot visibility без сохранения заведомо shadowed history.

## Tombstone safety

Newest tombstone удаляется только когда range bottommost и oldest active snapshot не требует pre-delete visibility. В противном случае tombstone остаётся output entry.

## Resource model

Compaction не использует unbounded allocation: общий estimated resident input ограничивается `max_compaction_bytes`, arithmetic checked. Однако v0.4 materialize-ит один выбранный job в памяти до этого лимита; fully streaming merge остаётся последующим улучшением.

## Обsolete files

v0.4 не удаляет input SST сразу после MANIFEST installation. Это сознательное ограничение: без отдельного reference-aware reaper удаление может быть небезопасно при старых Version/read handles и на Windows. Unreferenced SST не становится live при reopen.

## Release gate

GitHub Release создаётся только после release workflow: fmt, strict Clippy, workspace tests, doctests и release build с `--locked`.
