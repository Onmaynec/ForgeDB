# ForgeDB v0.6.2 — Memory & Reliability

## Цель

Убрать eager physical SSTable buffering из point-read `TableReader`, сохранив корректное чтение MVCC-версий, проверки persisted-формата и безопасное удаление retired SST на Windows. Расширить benchmark так, чтобы можно было проверять latency distribution, а не только общую продолжительность cold/warm прохода.

## Изменения

### Lazy SSTable reader

- `TableReader::open` больше не читает SST целиком. Он проверяет ожидаемый file size из MANIFEST, header, footer и checksummed filter/index/properties blocks через `FileSystem::open_random_access`.
- Data blocks открываются только при `TableReader::get`, `get_at_cached` и `latest_sequence_after_cached`, по validated BlockHandle offsets. Сохраняются reserved/trailer, compression version и CRC32C проверки.
- Физический file handle закреплён за `TableReader` до последнего reader reference; `Arc<Mutex<...>>` защищает общие seek/read операции. Продолжает работать reference-aware compaction retirement через Weak<TableReader>.
- Физическая SSTable структура и версия SSTable V1 не меняются.

### Benchmark

```bash
cargo run --locked --release -p forgedb --example point_lookup_bench -- 8192 50000
```

Измеряет холодный и тёплый проходы, выводит `throughput_ops_sec`, `p50_ns`, `p95_ns`, `p99_ns`, cache counters. Числа зависят от CPU, диска, allocator, системного кэша и конфигурации базы; без одинаковой среды нельзя заявлять ускорение относительно v0.6.1.

### Проверки

- Instrumented `FileSystem` проверяет, что открытие SST не читает весь файл.
- Повторное чтение того же проверенного блока из cache не приводит к дополнительным bytes-read.
- Corruption injection после `TableReader::open`: повреждённый data block обнаруживается при read, не попадает в LRU; последующий корректный read возможен.
- Existing snapshot versions across blocks, tombstones, WAL recovery, compaction, active iterator lifecycle и Windows tests сохраняются.

Новых migration steps нет.

## Ограничения

- `block_cache_size` ограничивает только decoded cache, не весь RSS.
- Index, Bloom filter, временные raw buffers, concurrent reads и memtables остаются вне cache budget.
- Каждый live `TableReader` удерживает OS file handle. `table_cache_capacity` пока не управляет eviction handles, поэтому очень большое число live SST может упираться в лимит FD.
- Reader не проверяет все data blocks при open: corruption обнаруживается при чтении блока или при независимом `verify --deep`. Уже кэшированные decoded blocks не перечитываются с диска на каждом hit.
- Cross-restart cleanup orphan files не вводится. Синхронные flush/compaction, snapshot isolation и все ограничения v0.6.1 сохраняются.
