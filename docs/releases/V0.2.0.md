# ForgeDB v0.2.0 — SSTable and Flush

Статус: **GitHub Pre-release**.

`v0.2.0` переводит ForgeDB от WAL-only базы к первому persisted LSM-слою: immutable memtable, SSTable V1, MANIFEST V1, numbered WAL generations и crash-safe synchronous flush.

## Возможности

- `Database::flush()`;
- mutable и immutable memtable generations;
- SSTable V1 с checksummed data/index/filter/properties blocks;
- prefix compression и restart points;
- versioned Bloom filter;
- MANIFEST V1 с checksummed `VersionEdit` frames;
- crash-safe `CURRENT`;
- point reads `mutable → immutable → L0 newest-first`;
- recovery current/previous WAL в разных memtable generations;
- типизированный `TableBuildRequest`;
- strict workspace lint policy без локальных исключений.

## Crash-safety

### WAL-first bootstrap

Initial WAL создаётся и синхронизируется до MANIFEST/CURRENT. После публикации `CURRENT` отсутствие MANIFEST-owned current или previous WAL является corruption.

### Generation-safe recovery

После crash между WAL rotation и SST installation previous WAL восстанавливается в immutable pending memtable, а current WAL — в mutable. Следующий rotation запрещён до установки pending generation.

### Retry-safe orphan handling

- header-only orphan WAL повторно используется только после проверки UUID, file number и отсутствия frame/tail;
- non-empty/partial orphan WAL сохраняется и блокирует flush;
- SST retry удаляет только доказанный non-live reserved number;
- unknown/user files normal recovery не удаляет.

### Durable SST installation

SSTable становится live только после полной проверки и durable MANIFEST installation edit. Obsolete previous WAL удаляется только после успешного sync этого edit.

## Corruption policy

- persisted headers, offsets, lengths, reserved fields и CRC32C проверяются до использования;
- unknown future versions отклоняются;
- checksum mismatch live SSTable блокирует open;
- normal recovery не выполняет resynchronization после mid-file corruption;
- corruption tests детерминированно изменяют сохранённый CRC через XOR.

## Ограничения

- только Level 0;
- нет leveled compaction;
- нет range iterator и snapshots;
- нет transactions;
- flush синхронный, без background worker и write stalls;
- SSTable reader bounded-загружает файл целиком;
- CLI inventory/verify появится в следующем milestone.
