# ForgeDB v0.6.0 — Cache and Performance

## Цель

Устранить повторное полное чтение SSTable при point lookup и transaction conflict validation, добавить управляемый decoded-block cache и безопасную process-local очистку доказанно retired SST после compaction.

## Реализовано

- Snapshot-aware `TableReader::get_at_cached` с SST Bloom filter и index; поддержка MVCC-версий одного user key между физическими data blocks.
- `VersionSet::get_at` больше не вызывает полный `table_scan::read_entries` при обычном point read. L1+ выбирает единственный candidate бинарным поиском.
- `VersionSet::latest_sequence_after` проверяет только подходящие index blocks и сохраняет write-write conflict semantics.
- Bounded `BlockCache` для decoded data blocks, доступный через `Options::block_cache_size` (`0` disables residency).
- `Database::cache_stats()` возвращает `CacheStats`: hits/misses/evictions/bypasses, resident_blocks, resident_bytes, capacity_bytes.
- `DbIterator` удерживает `Arc<VersionSet>`, пока выполняет scan.
- При synced compaction edit input SST ставятся в process-local retirement queue с per-reader weak references.
- `cleanup_obsolete_sstables()` conservatively удаляет только файлы, исключённые из live MANIFEST и больше не удерживаемые читателями; CLI `compact` выполняет эту очистку и печатает отчёт.
- Добавлены unit/integration тесты на snapshot visibility, tombstones, split block boundaries, cache eviction/disabled, transaction conflicts, active iterator lifetime, orphan preservation после restart.
- Повторяемый benchmark `point_lookup_bench` и Linux/Windows smoke-run.

## Persisted-format impact

**Нет**. WAL V1, SSTable V1, MANIFEST V2 (reader V1/V2) и CURRENT V1 не изменены. Cache не изменяет physical SST bytes и не формирует persisted metadata. Доказательство retirement следует из synced MANIFEST edit, а не из предположения о файлах каталога.

## Crash consistency

При crash до установки compaction output не становится authoritative; после synced installation удаляемый input больше не live. Cleanup никогда не меняет MANIFEST. Failed OS unlink оставляет файл на диске и доступен повторной очистке в рамках данного open handle. Неподтверждённые orphan-файлы после restart не удаляются автоматически.

## Performance measurement

```bash
cargo run --locked --release -p forgedb --example point_lookup_bench -- 8192 50000
```

Benchmark создаёт временную базу, измеряет cold/warm point reads и выводит cache counters. Без повторных запусков в одинаковой среде и baseline v0.5.0 проценты ускорения не заявляются. CI smoke-run используется для регрессии работоспособности, не для SLA.

## Ограничения

- Физический `TableReader::open` по-прежнему eager загружает SSTable bytes; decoded-block cache не ограничивает общий RSS, и `Options::table_cache_capacity` пока не включён в рабочий путь.
- Range iterator сохраняет отдельный block-at-a-time cursor и не использует point cache.
- Полноценная background GC и cross-restart orphan cleanup отсутствуют. `cleanup_obsolete_sstables` удаляет только известные process-local retired inputs.
- Compaction synchronous, merge bounded `max_compaction_bytes`, но материализуется внутри бюджета.
- MVCC transactions — snapshot isolation, не serializable.
- No external dependencies; persisted formats неизменны.
