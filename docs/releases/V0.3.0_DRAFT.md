# ForgeDB v0.3.0 — Full LSM Read Path

Статус: **stacked draft, не выпущено**.

Версия строится поверх draft `v0.2.0 — SSTable and Flush`. Merge, tag и GitHub Pre-release запрещены до завершения базовой версии и полного validation gate.

## Основные изменения

- MVCC memtable сохраняет все internal-key versions.
- `Snapshot` фиксирует sequence и остаётся видимым через overwrite, delete и flush.
- `ReadOptions` выбирает snapshot и checksum policy.
- Immutable `Arc<VersionSet>` отделяет readers от writer mutex.
- L0 читается newest-first.
- L1+ моделируются со строгими sorted/non-overlap invariants.
- `Database::scan` объединяет sorted sources через binary heap.
- Range output скрывает shadowed versions и tombstones.
- Previous/current WAL поколения восстанавливаются в разные memtables.
- `FileInventory` классифицирует live, obsolete, orphan, temporary, backup, user и unknown objects.
- `RecoveryPlan::inspect` показывает authoritative MANIFEST, WAL replay order, live SSTables, warnings, blockers и только proposed cleanup.
- Quick/deep verify проверяет VersionSet, inventory и live SSTables.
- CLI получил `scan`, `inventory`, `inspect recovery-plan` и `verify --deep`.

## Persisted-format impact

Новые persisted-форматы отсутствуют. Используются версии 1:

- IDENTITY;
- Internal Key;
- WAL;
- SSTable;
- MANIFEST;
- CURRENT.

MANIFEST V1 сохраняет L0. L1+ в этом milestone существуют как validated in-memory structure и будут физически заполняться compaction milestone `v0.4.0`.

## Snapshot contract

Snapshot принадлежит конкретному `DatabaseId` и конкретному open handle. Он не сериализуется и не может использоваться после reopen.

Первая версия user key с `sequence <= snapshot_sequence` определяет результат. Tombstone завершает поиск и скрывает нижележащие значения.

## Range scan contract

- forward-only;
- user keys по возрастанию;
- не более одной user entry на key;
- optional exclusive end bound;
- optional output limit;
- один sequence на всю операцию;
- corruption любого выбранного live source завершает scan ошибкой.

Текущий draft всё ещё декодирует выбранные SSTables целиком перед heap merge. Block-at-a-time cursor остаётся обязательным acceptance gap до выпуска.

## Recovery plan contract

`forgedb inspect recovery-plan <каталог>` выполняет только чтение под process lock. Команда не перемещает и не удаляет файлы.

План содержит:

- selected MANIFEST;
- previous/current WAL replay order;
- live SSTables;
- obsolete, orphan, temporary, backup, user и unknown files;
- planned safe cleanup;
- warnings и blockers;
- возможность normal open.

Unknown и user files никогда не включаются в автоматический cleanup.

## Validation gate

Перед выпуском обязательны:

```text
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-features
cargo test --workspace --doc
cargo build --workspace --release
```

Матрица:

- Ubuntu stable;
- Windows stable;
- Ubuntu Rust 1.89.

На текущем head GitHub-hosted jobs завершаются до checkout и не предоставляют compiler/test result. Повторный запуск создаёт новые job IDs с пустым списком steps. Поэтому версия не тегируется и не публикуется.

## Оставшийся acceptance gap

- заменить materialized SSTable sources на block-at-a-time cursors;
- доказать bounded resident memory тестом на многофайловом range;
- выполнить canonical rustfmt и compiler/Clippy pass;
- пройти полную CI-матрицу после восстановления runners.

## Ограничения

- Нет compaction.
- L1+ физически пусты.
- Нет block/table cache.
- Scan bounded-декодирует выбранные SSTables целиком.
- Нет backward iterator.
- Нет transactions и column-family API.
- Inventory и recovery plan не изменяют файлы автоматически.
